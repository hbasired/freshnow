The answer in one slide

Four questions, four answers

1 · Can we host the database and system on Hostinger?

Yes, it can be lawful. The PDPL has no rule forcing employee data to stay in the UAE. But every record on Hostinger is a transfer abroad, and today only two grounds work: each employee's express consent, and a contract that imposes the law's controls — whose use for an EU country is unsettled. So: an EU data centre, consent (built — notice 2.0), Hostinger's DPA accepted, and the security controls on slide 6. [believed — counsel to confirm]

2 · Can we keep Groq or OpenRouter?

For code or anonymous text: yes, freely. For employee words: only with consent (built), their zero-data-retention settings on, and names and numbers removed first. Both have improved since our last deck — Groq now offers every account a zero-retention switch and a DPA; OpenRouter does not log prompts by default and can force zero-retention routing — but both still process in the US. [believed — slide 7]

3 · Can "policy as code" make sure there is no violation?

It can make known violations impossible to deploy or to run — an AI provider nobody registered, a message to someone who has not agreed, retention unset, backups unencrypted — and it produces the evidence. It cannot sign a DPA, decide what the law means, or see inside Hostinger. "No violation" is a legal conclusion: counsel draws it, code enforces it and proves it. [slides 8–11]

4 · What do we recommend?

A UAE host + Core42 for the AI — though not because it is cheaper. Like for like (8 vCPU · 32 GB), Hostinger's KVM 8 is $25.99 a month prepaid, then ≈ $49.99; the cheapest Dubai servers of that size are ≈ $74–80, and AWS or Azure in the UAE $189–310+. Hostinger saves about $300 a year at renewal. What it costs instead is a permanent transfer of the whole database, resting on consent any employee can withdraw. If the company takes the saving: Option B, with every condition on slide 6. [prices believed, 29 Sep — slides 13–14]

Where enforcement stands (29 Sep 2026)

  • Executive Regulations: still pending (Ashurst, July 2026) [believed]
  • Adequacy list and contract templates: not issued [believed — ABS Partners, Kayrouz 2026]
  • A Federal Authority for AI and Data exists since 14 June 2026 and absorbed the Data Office [believed — four reports]
  • Five search claims that named an "issued" Regulations instrument have been traced and found false — which is why every legal status here carries a marker.

What that means for choosing a host

Nothing forbids Hostinger today and nobody is auditing today. But a choice made now has to survive the day the Regulations arrive — they may add procedures for exactly the transfers Hostinger would require, with six months to comply. A UAE host is the only choice those Regulations cannot touch.

If Hostinger: which data centre

Hostinger's VPS locations: France, Germany, Lithuania, UK, India, Indonesia, Malaysia, USA (Phoenix, Boston), Brazil — none in the UAE or the Middle East. [verified 21 Sep on Hostinger's page] [re-checked 26 Sep and 29 Sep via search]

Choose an EU location — Lithuania (Hostinger's home) or Germany — so the data sits under GDPR, the strictest regime on offer. Avoid the US, India, Indonesia, Malaysia and Brazil.

The weakness of consent as the only ground

Consent can be withdrawn at any time, and in an employment relationship whether it is freely given is contested. A person who says no must still be able to work — without the system, or through a UAE-only path we have not built. With a UAE host the database needs no ground at all; only Telegram does.

Policy as code · what it means for us

Write the compliance rules down once — and let the system refuse to break them

"Policy as code" means the rules live in files the system reads and checks, not in a PDF people forget. For FreshNow that is five layers — three of them already exist.

Policy as code · the registry and the rules

One file says where personal data may go; the system checks itself against it

The registry — compliance/processors.yaml design

Policy as code · its limits

What no amount of code can promise

It cannot sign or negotiate

Accepting Hostinger's DPA, asking for UAE clauses, getting Core42's terms in writing — people do these. The registry only refuses to proceed until they are recorded.

It cannot decide the law

Whether consent from an employee is valid, or whether Art. 23(1)(a) covers an EU country, is for counsel. Code enforces the answer once it exists.

It cannot see inside Hostinger

Their staff, their sub-processors, the machine under our VPS. The DPA and encryption we hold the keys to are the only controls there.

It cannot stop hand copying

A screenshot, a forwarded Telegram message, an export. That is policy, training and access roles.

It cannot foresee the Regulations

When they arrive, the rules change. The registry makes that a one-file change, re-checked and re-consented automatically.

What it does guarantee

That a known rule is never silently broken by a deploy or a configuration change — and that every claim of compliance can be shown from the database.

So "without any violation" is three things together: counsel's reading of the law · the company's contracts and decisions · code that enforces both and keeps the evidence. Code alone is one of three.

"Dubai VPS" is not proof of Dubai

Some sellers rent an IP address that looks Emirati and run the server in Europe. Before ordering: get the data-centre name and address in writing (e.g. Equinix DX1, Dubai) and put it in the contract; ping the server from Dubai — a local server answers in a few milliseconds, Europe in about 100; an IP-location website is not evidence.

A UAE data centre, a foreign company

Most of these companies are based abroad. The data stays in the UAE, but their support staff may reach the server from elsewhere — which can itself count as access from abroad. Ask where administrative access comes from, and put it in the DPA. AEserver and BlessHost are the UAE-based companies in the list.

Decision and next steps

Choose A or B — then this is the order of work

If A — UAE host + Core42

  1. Order the Dubai VPS — data-centre name and address in the contract (slide 14); buy the domain. CEO · an hour
  2. Move the Docker stack unchanged; Caddy gives HTTPS; phones use the domain — no tunnel. developer · days
  3. Switch the AI to Core42; remove the US fallbacks. The notice rewrites itself; everyone agrees again. developer · hours after sign-up
  4. Registry + rules R1–R8 (slide 9). developer · about a week in total estimate
  5. Company: retention number, breach contact, notice wording, counsel's read.

If B — Hostinger (EU)

  1. Counsel confirms consent + DPA for a permanent EU database — before ordering.
  2. Order the VPS in Lithuania or Germany; accept and file the DPA; turn on two-factor sign-in.
  3. Add the host line to the notice; everyone agrees again before real data goes in.
  4. Harden the server; encrypted backups with a second EU copy; DB access log (slide 6, rows 8–12).
  5. Registry + rules R1–R8, with hosting_countries_allowed set to the EU.
  6. Decide the path for anyone who does not consent.
Either way, one thing is already done: consent is asked, enforced and recorded in Telegram and the app, and it follows the configuration automatically. What remains is a choice of host, a few contracts, and the registry that makes every future change safe.
