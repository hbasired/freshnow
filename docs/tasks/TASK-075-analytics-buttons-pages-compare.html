Why it was done this way

  • The server recounts on a category choice, the page does not add. Unpressing Expo changes the average, so every tier, rank and sentence must be worked out again over the remaining machines — the same rule TASK-070 set: every figure counted by Postgres and fixed code, the page only draws. A round trip is under 0.1 s here, and the page holds its last render while it counts.
  • "Last week same day" is always 7 days back, per day. The user asked for it by name, and weekday patterns make "the day before" a misleading comparison (research below). The period's own change still compares whole weeks earlier, over pairs read on both sides.
  • Differences from exact totals. 16 against 21.33 cups a day is +33.3 %; from the rounded 21.3 it would be +33.1 %. The test fixture makes both visible, and the cash move too (−20.3 points, not the −20.4 of the rounded shares).
  • The answer right under the button. The machines' list used to sit below a chart over 2,000 px tall; now the table is the first thing under the tier buttons, the chart follows and shows the same machines. A table beside the chart was tried at desktop width and squeezed the names into four lines; it got the full width.
  • Pages, not panels. The user asked for new pages; each is a link, so it can be sent, bookmarked and gone Back to.
  • Two peer hues for A and B. A and B are not "now against before", so they cannot be the accent-and-gray emphasis pair; the blue/orange pair was validated against the panel in both themes. The machines that moved are one neutral hue, so the sign is said by direction and label, never by A's or B's colour.
  • No new dependency. Recharts was already in the dashboard (TASK-058/070).

How it works

  1. The page sends the days and the categories chosen (a JSON array) to /performance and, for the Overview and Trends, /profile?scope=selection.
  2. Core checks the reader (televend.read), the range (whole days, up to yesterday, at most 92) and the names; Postgres reads the days the store holds checked, credits each record's day and hours to FreshNow's machine through the placements, and joins each machine's facts from machineInfo — all under the viewer's row security, read-only.
  3. Fixed code adds up the scope's machines per day and over the period, pairs each day with the same weekday a week before, works out the changes from the totals and fills the sentences, each with the figures it states.
  4. A comparison builds two profiles and the rows of differences; the page draws the table and the charts.

Concepts and techniques

  • Same-weekday comparison — a day against the same weekday a week before cancels the weekday's own pattern; a period against the same weekdays whole weeks earlier, over pairs read on both sides only.
  • Scope — one profile function for the categories chosen, a category or a machine, so every page has the same charts and the same meaning of a number.
  • Settled input — several taps count once (250 ms); "refetch keeps the frame" — no skeleton, no jump.
  • Numeric gate in tests — every figure in a sentence must be in its own list (names and dates of the month aside, thousands separators understood).
  • Emphasis pair vs peer pair — accent/gray for now against before; two validated hues for A against B; one hue and direction for signed changes; every chart has a table twin.

Research findings

  • Vending dashboards in use show total revenue, transaction counts, average transaction value, hourly peaks and per-machine payment breakdowns (a Power BI vending offering, Parlevel's ROI by machine, VendCell, PayRange) — the figures added here (income per paid cup, busiest hour, payment mix per machine) match. No benchmark values were found.
  • Same-weekday comparisons are the common pattern where weekday seasonality is strong; day-over-day mainly for spotting anomalies (Enterprise DNA forum, Oracle's weekday comparison report, a retail dashboard template). Compare offers "yesterday vs the day before" as an explicit choice, not as the default.
  • Recharts: the newest notes found are 3.10.0 (Legend position/offset, XAxis height="auto"); nothing changed for vertical grouped bars (3.10.0 notes, changelog). The dashboard pins 3.10.1.

What we have not verified

  • Real data: every screen was checked on synthetic machines and sales in this container. The live mirror (about 100 records, 208 days) was not read from here; how the pages look and how fast they answer on it is not known.
  • Real use: nobody at FreshNow has used the new pages; whether the sentences and the layout answer the Ops Head's questions is untested.
  • The thresholds: "under 5 % is noise" for the last day's sentence (A-T75.1) and the first 15 machines before "All" are defaults, not FreshNow's.
  • Income: still an estimate from the prices (A-T70.1, A-T70.3), and wallet and other payments are counted at the card price (A-T75.2).
  • Phones: checked at 390 px in a headless browser, not on a real phone; long category names in the buttons were not tried.
  • Accessibility: keyboard focus and screen-reader names were checked only where the browser script used them (buttons, tabs, radios, labels); no screen reader was run.
