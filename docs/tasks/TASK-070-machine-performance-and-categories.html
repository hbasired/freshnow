Why it was done this way

Only days that were read

The sync records which stretches of time it read to their end. A day counts only when it lies wholly inside them; any other day is named on the page and left out, and per-day figures divide by the days read. A day the mirror did not read is never a day with no sales — the rule the Operations pages already followed (TASK-058 review).

The same weekdays, whole weeks earlier

Sales follow the week. Comparing Monday with Sunday would read a weekday pattern as a change, so the period before is shifted by whole weeks: yesterday against the same weekday a week before (the user's "previous week's same day"), ten days against the ten days two weeks before.

Levels per machine that sold; changes on volume

The fleet average counts only machines that sold, so a broken machine does not pull the bar down for everyone — those are listed apart as "sold nothing". But a change computed on that average moves whenever a machine starts or stops selling. The first version did exactly that and said "Sales rose 6.2 %" while cups fell from 476 to 420 (one machine stopped). It was found by looking at the browser check's screenshot, not by the tests, which had been written to the same rule (G210). Every change is now on volume — cups per day for the same machines — and the average is shown as a level with its value before, without an arrow.

Colour that means something

Above, about and below the average is one scale with a middle, so it is drawn as a diverging scale — the existing accent blue, the base gray, and a new orange validated in both themes with the data-viz validator — and every tier is also written in words. Nine categories would need nine colours; the palette stops at eight, so categories are compared on one-colour bars and small charts.

Not built here

  • History before 3 Oct (TASK-071 copies it back), the full machine page and the sales list (072), exploring a day or range across everything (075), any ranking of people — the figures are about machines and places.

How it works

machinePerformance(viewer, {from, to}) runs three queries under the viewer's row security: the days read (time-range sets from tv_sync_run), one row per machine (sales on read days, summed by Televend machine id and joined to FreshNow's machine through its current placement, with category, price and card-only read from the names), and each category's cups per read day. Tiers, the 80 % set, category figures and the sentences are worked out from those rows; each sentence carries the numbers it states, and a test checks that no number appears in a sentence that is not in its list.

Since the review of 20 Oct (D257): the figures come from the TASK-071 store, not the raw mirror — a day counts only when its latest build agrees with Televend's own count. A change compares only the days read on both sides, from the totals. Each Televend record's sales count for the FreshNow machine it stood in that day: the placement in force at the day's end, else its number, else the record itself.
