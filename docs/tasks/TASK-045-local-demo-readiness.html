One-sentence summary: Preparing the laptop demo of the app channel found that a phone could never both sign in and receive notifications — sign-in went to a second, plain-HTTP port while notifications need HTTPS — so sign-in now goes through the dashboard's own address; the board no longer loads before consent; assignment wording no longer says "Telegram"; CI is manual-only; and a step-by-step guide covers starting everything, three accounts on three screens, and the demo end to end.

Why

A browser grants notifications only to a secure page, and a secure page may not call plain HTTP. With sign-in on http://<laptop>:54321 the only choices were "sign in over the LAN without notifications" or "an https page that cannot sign in". Putting the three sign-in calls behind the API makes page and sign-in one origin; the alternative — a second tunnel for 54321 and a dashboard that knows two public addresses — adds a moving part for no benefit. The allow-list is narrower than what port 54321 exposes today (the local config allows self sign-up; the pass-through does not).

What we have not verified

  • A real phone. The first real phone notification will be the demo itself. The service worker could not be registered on the local HTTPS front because its certificate is self-signed; Cloudflare's is not, but that was not tested here.
  • The Supabase CLI's own stack. Tested with GoTrue built from source, HS256 keys and a hand-written gateway, not the CLI's Kong and ES256 keys. The pass-through does not touch verification, so the difference should not matter — unmeasured.
  • Cloudflare quick tunnel: install command and behaviour taken from Cloudflare's documentation via search; not run here. Its traffic passes through Cloudflare (US) — acceptable for a demo with test data, not for real employee data.
  • Windows specifics in the guide (winget, PowerShell syntax, Windows notification settings) were written for Windows but executed on Linux.
  • Existing browser sessions sign in once more after this change (the session key follows the address). Expected, not observed on the laptop.
