TASK-015 — Replay

Phase 1 (demo) · 2026-09-04 · Satisfies SPEC-000 R7/R8 (a stored run is reconstructible and re-executes to the same decision) · 60/60 tests green.

What was done

  • Refactored routing into a pure, side-effect-free resolveForCategory(category) used by both routeBlocker and replay.
  • packages/core/src/replay.ts — replayRun(correlationId): reads the run's run_trace + audit_log "blocker.routed" rows, re-derives the routing decision from current reference data, and returns a divergence report.
  • Tests — no-divergence (recorded == re-derived) and divergence-detected (a recorded decision that no longer matches).

Why it was done

SPEC-000 R7/R8: any decision must be reconstructible from stored state and re-executable to the same result. If the routing table changed since a run, that is a legitimate divergence — and it must be reported, not silently produce a different answer. This is what lets a CEO trust that "why did this go to X?" has a stable, auditable answer.

How it works

replayRun(correlationId)
  read run_trace steps (count) for display
  read audit_log where action='blocker.routed'  → original resolverId per blocker
  for each: re-derive resolveForCategory(blocker.category)  ← current lookup
            compare original vs re-derived
  → { steps, checks:[{blockerId, original, rederived, matches}], diverged }

Concepts and techniques used

  • Deterministic replay — same inputs + same reference data → same decision.
  • Pure-function extraction — the routing lookup has no side effects, so it can be re-run safely.
  • Divergence reporting — a changed reference table surfaces as a reported difference, never a silent one.

What we have not verified

  • Only the routing decision is replayed. The parse step is LLM-based (non-deterministic) and is deliberately not replayed for equality; escalation and assignment replay are not yet implemented.
  • Replay compares the recorded resolver to the current lookup; it does not re-run the whole pipeline or diff every field.
  • Tested on single-blocker runs only.

Open questions

  • Extend replay to escalation and (later) assignment decisions, and to a full step-by-step trace diff.
