TASK-001 — Foundation

Phase 1 (demo) · 2026-09-04 · Satisfies the Task-board T1 and the CLAUDE.md stack/layout rules · Sets up the monorepo, local infrastructure, typed config, test harness, knowledge base, and the demo↔production deviation record.

What was done

  • pnpm monorepo — package.json, pnpm-workspace.yaml, strict tsconfig.base.json + root tsconfig.json, with five workspace packages: @freshnow/core, /api, /bot, /worker, /dashboard (the last four are typecheck-clean placeholders until their tasks).
  • Local infrastructure — docker-compose.yml running pgvector/pgvector:pg17 and redis:7-alpine, both bound to 127.0.0.1, with health checks. Postgres is published on host port 5433 (see gotcha below).
  • Typed configuration — packages/core/src/config.ts parses the environment through Zod; config.test.ts covers defaults, the bigint coercion of the CEO id, and rejection of bad input (5 tests).
  • Environment — .env.example (documented placeholders, no secrets) and a gitignored .env for local dev.
  • Knowledge base — knowledge-base/ with 00-INDEX.md, decisions.md, assumptions.md, verified-facts.md, gotchas.md.
  • DEVIATIONS.md — every demo↔production difference with a one-line switch-back.
  • Test runner — Vitest at the workspace root.

Why it was done

CLAUDE.md rule 1 ("Telegram is a channel, not the system") requires all domain logic to live in packages/core, called identically by the bot, API, worker, and dashboard. A workspace with a shared core is the structure that makes that rule enforceable and makes the later Phase-4/5 adapters additive rather than a rewrite.

The company has not supplied real data, so this is a local demo that mirrors production. The honest way to do that is to keep the behaviour real and record every place the demo diverges — hence DEVIATIONS.md. The four divergences (polling vs webhook, plain Postgres vs Supabase, Groq/NVIDIA vs OpenRouter, local Whisper/Piper) are transport/packaging/vendor choices, not behavioural fakes.

Build-free TypeScript. Each package's exports points at ./src/index.ts and dev runs through tsx; typecheck is a single root tsc --noEmit. This removes a build step for the demo. The trade-off: the packages are only consumable from within this workspace (fine here).

How it works

host (Windows) ── docker compose ──▶  freshnow-db   (Postgres+pgvector)  127.0.0.1:5433
                                      freshnow-redis (Redis)             127.0.0.1:6379

pnpm workspace
  @freshnow/core   ← loadConfig() (Zod), later: db, llm, domain logic
  @freshnow/api    → imports core            (Fastify server: Task 003)
  @freshnow/bot    → imports core            (grammY bot:     Task 006)
  @freshnow/worker → imports core            (BullMQ jobs:    Task 005)
  @freshnow/dashboard                        (Next.js:        Task 012)

loadConfig() validates process.env and fails with a readable, field-by-field message. Telegram ids are coerced to bigint at this boundary (32-bit truncation is a known identity-corruption bug — gotcha G2).

Concepts and techniques used

  • pnpm workspaces — one lockfile, symlinked internal packages via the workspace:* protocol.
  • ESM + NodeNext resolution — relative imports carry a .js suffix even for .ts sources; verbatimModuleSyntax forces explicit import type.
  • Boundary validation with Zod — untrusted input (the environment) is parsed into a typed value once, at the edge.
  • Documented deviation register — a demo that mirrors production is only honest if every difference is written down with how to revert it.
