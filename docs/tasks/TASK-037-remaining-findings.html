2 · The two things I had marked "reasoned, not exercised"

The Telegram sender timeout — exercised

A local HTTP server that accepts the connection and never responds, which is what a black-holed link looks like to fetch. The sender rejected after 20.04 s. Before the fix it would have waited forever, inside the relay's open transaction, holding row locks, with the worker loop stopped.

The fail-open warning — exercised, and it found a trap in the test itself

Starting the API with SUPABASE_URL= (empty) fails closed: config validation rejects it and the process refuses to start — safer than I had claimed. The fail-open case is the variable being absent. And unsetting it in the shell was not enough: import "dotenv/config" re-injected it from .env, so my first probe was testing a system with auth on (the 401 said so). With dotenv pointed at an env file without the key: the warning printed once, and /dashboard/me?viewer=ceo answered isCeo: true — the exact state the warning describes.

The config rule that would have broken every model call

Adding webhook config, I wrote TELEGRAM_WEBHOOK_SECRET: z.string().min(16).optional(). Two facts combined: .env has that variable set to an empty value (harmless in polling mode), and loadConfig() is called inside llmCompleteInner on every model call. The rule threw on every one. The question-box tests caught it — "I couldn't produce a safe query" on a perfectly good query — before it reached a running service. The length rule now lives in the webhook branch, where it belongs. Recorded because a validation rule that is right in one mode and fatal in another is exactly the kind of thing a test suite exists to catch, and it did.

What we have not verified

  • Webhook mode has never received a real update from Telegram. The listener, the secret check and setWebhook are tested against a local socket and a stub bot. It has not been run behind Caddy with a public HTTPS URL, because there is no domain yet (WHAT-WE-NEED-FROM-FRESHNOW.md §6).
  • The retention window is unset and will stay unset until FreshNow's data controller chooses one. The sweep runs hourly and says so; nothing is aged out today.
  • Erasure has no UI or command yet. eraseEmployee is a core function with tests; nothing calls it. The reset script still hard-deletes, which is the demo tool's job — but a production "this person left" action should call this instead.
  • The grounding gate's claim detector is a regex. It will miss a policy claim phrased unusually and may flag an innocent sentence containing "must be". Both errors are visible (the gate verdict is shown), and the failure direction is a withheld sentence, not a false one.
  • Routing by site/shift is tested but the live table has no site or shift rules — every seeded rule is category-only. The company's table (§1.1 of the needs document) is what exercises it for real.
  • The EOD gate has not been seen to fail on a real narrative; the fallback path is tested by reasoning.
