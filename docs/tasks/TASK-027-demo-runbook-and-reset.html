3 · The defect the reset tool was carrying (G69)

The script was written before daily_report (migration 0003) and attachment (0004), and no foreign key in this schema uses on delete cascade. Deleting an employee who had filed an end-of-day report or uploaded a file would have failed with a foreign-key error — at the worst possible moment, leaving a half-deleted person. Attachments are now deleted first (they reference assignments, tasks, updates and the uploader), then the rest in dependency order, then daily reports, then the employee.

Rule to carry forward: when a migration adds a table with an employee foreign key, add it to this script — or give the key a cascade and say so in the migration. A cleanup script is invisible until the day it fails.
