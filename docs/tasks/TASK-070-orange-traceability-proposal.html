Why it was done this way

  • Plan and prototypes only, no platform code. The user asked for "only the plan … and HTML of it", and CLAUDE.md step 3 requires confirmation before multi-file work. More decisively, the real code base (TASK-055 → 069) is not on GitHub: building the WMS on the 7 Oct main would create a third line of history. The deck's last decision is to push it first.
  • Weigh at the tailgate instead of two zones: the theft window the user worried about exists only because weighed crates wait. Moving the scale to the door removes the window and halves the scans with the same hardware.
  • Weights are the record; cameras are evidence. Hidden crates, glare and occlusion make camera counts fail silently, the one failure an audit system cannot afford. A camera that bookmarks each scan gives proof without being the count.
  • Build inside the platform, borrow the models. One Postgres, one permission model (RLS), one audit log, one alarm engine and one staff app beat a second ERP whose records would have to be kept in step with ours — and ERPNext would need MariaDB.
  • REST for devices, MCP on top. CLAUDE.md rule 2 keeps models out of computation; a device protocol through an AI tool layer would violate it. The local build's read-only MCP server (D184) is the right place for MCP.
  • Voice: fixed rules first, a model only for grounded gaps. Mirrors the numeric sanity gate: a number the system shows must come from its source — here, the words heard.
  • Plan aligned with the local build. The TASK-055/056 notes in the 23 Oct push showed the Televend mirror (vends, refills in cups), machine QR stickers, a Flutter staff app, built-in chat and an MCP server already decided; the deck reuses them instead of proposing parallel answers (e.g. kg delivered vs cups refilled vs cups sold needs no new hardware).

How it works

Deck

Slides are written as six fragments and assembled by a build script (kept outside the repository) that numbers slides, resolves cross-references written as keys (so "slide 15" stays right when slides move), embeds the fonts and writes two files: the repository copy (a full HTML document) and an artifact copy. Presentation mode computes scale = min(width/1920, height/1080) and transforms the stage; a media query (max-width:900px),(max-aspect-ratio:1/1) switches to reading mode. Charts are inline SVG on a fixed scale with hover read-outs that convert screen to stage coordinates.

Demo animation and video

render(t) — every crate position, the scale reading, scanner, beam, Wi-Fi packets, table rows,
            banners, manifest, captions — is a pure function of t ∈ [0, 72]
live:   requestAnimationFrame → t += dt → render(t)
video:  deck.html?record#s12 → for f in 0..2160: seek(f/30); screenshot → ffmpeg (libx264, CRF 21, +faststart)

Because nothing depends on wall-clock time (CSS transitions are off in the demo), the recorded frames equal what the slide shows.

Voice page

button / Space ─► getUserMedia ─► MediaRecorder (WebM/Opus, ≤ 15 s)
               ─► POST /audio/transcriptions (whisper-large-v3-turbo, language, temperature 0, format-biasing prompt)
               ─► normalize: number words → digits, "point five", "and a half", "no 3", "18,5"
               ─► fixed rules: crate · weight (kg) · plate after the LAST vehicle word
               ─► missing field? POST /chat/completions (json_schema, strict; one retry in json_object mode; 10 s timeout)
                    └─ value accepted only if it appears in the transcript, else ignored and flagged
               ─► row on top · read-back · CSV

Concepts and techniques used

  • Double-entry inventory with virtual locations — every movement has a source and a destination, including places outside the business (garbage, charity, sold, cups sold, moisture loss, unexplained), so losses become visible balances (Odoo's model).
  • License plate numbers (LPN) — an ID on every container scanned at each move (Manhattan); here, the crate QR plus a fill record.
  • Mass balance — input weight equals the sum of outputs plus expected loss; the remainder is the number to investigate.
  • Tolerance from physics — alarm when shortfall exceeds the highest expected moisture loss for the elapsed hours plus two scale divisions; with the assumed rates one orange stands out for trips up to ~11 h at 10 g resolution.
  • State machine with refusal — the station cannot be scanned out of order; refusals are logged, not lost.
  • Grounding gate — a model's output is accepted only when its value can be found in the source text.
  • Deterministic rendering for capture — render as a function of time, then sample it; the same technique video tools use.
  • Secure context — microphone APIs need one; Chromium grants it to file:// pages (VF-T70.1).

What we have not verified

  • Groq itself. This environment's proxy refuses api.groq.com, so no real transcription ran and whether Groq answers a browser page's cross-origin request is unknown. The page explains the failure and offers Chrome's built-in speech and typing.
  • Whisper's accuracy on real speech in a noisy warehouse, and with Gulf, Hindi or Malayalam accents — not measured.
  • No scale, scanner, bridge, camera or tracker was bench-tested. RS232 frame formats, the USR-W610 HTTP mode and the NETUM DS2800 HTTP output come from listings, not from the devices or their manuals.
  • Prices are search-result snapshots of 23 Oct 2026; Amazon.ae could not be opened directly; several items have no captured price.
  • SIRA requirements come from installers' guides; PDPL points are a technical reading for counsel.
  • Orange weight (131 g) and moisture-loss rates are not FreshNow's; the 11-hour figure is arithmetic on them.
  • UHF RFID read rates through crates of oranges; phone-camera scan speed vs a scanner gun — not tested.
  • The 20 Oct local build (analytics, MCP, inventory, routing, TASK-055 plan) was seen only through notes in the 23 Oct push; the deck may duplicate or contradict parts of it until merged. The analytics redesign is a plan against code we have not read.
  • The deck in the claude.ai artifact viewer: keyboard focus needs a click first; video playback from the artifact's own files was not tested from here.
  • Reading mode (phones) was checked by layout rules only, not on a phone.
