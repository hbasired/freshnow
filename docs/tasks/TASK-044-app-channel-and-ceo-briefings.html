3 · Why it was done this way

Presets over the switches, not a new setting. The switches already are the source of truth for the outbox gate; a separate "primary channel" field would be a second truth that can disagree with them. A preset is a way of setting two switches at once, and the audit log keeps both the decision (channel.mode_set) and each effect (channel.toggled).

Refuse, don't warn. The system exists so that a blocker raised is a blocker heard. Turning Telegram off with nothing that reaches a closed phone is exactly the failure it prevents, so the server refuses it; the UI greys the button and says why.

A device is consent enough for push; an address is not enough for email. A push subscription only exists after two explicit acts by the person themselves. An email address can be typed in by an administrator.

Keep old idempotency keys. Rows already in the outbox under needs-review-<id> must not be re-sent, so notifyPeople takes the key shape from the caller.

Why a deck recommends Azure over AWS although AWS is cheaper on paper: AWS's own status update says data held in one UAE zone after the March strikes cannot be restored and advises moving; Azure pairs Dubai with Abu Dhabi, so a second copy can stay in the country. Cost difference for our size: ~$50–60 a month.

5 · Concepts and techniques used

  • Transactional outbox — business logic writes a row; a worker delivers. The gate sits in the one function every message passes.
  • Structural idempotency keys — <event>:<entity>:<person>:<channel>; a retry sends nothing twice.
  • Web Push with VAPID — RFC 8291 message encryption to each device's keys (the relay sees ciphertext); RFC 8292 VAPID identifies the sender; RFC 8030 Urgency lets a blocker wake a sleeping phone.
  • Notification tags and renotify — the same problem replaces one banner, and still buzzes.
  • Consent bound to a hash of the words shown — the record proves what was agreed; stale pages are refused.
  • Make-before-break — enable the new path before disabling the old one.
  • Geo-redundant storage across a paired region — a backup copy in another emirate without leaving the country.

What we have not verified

  • No real push service and no phone. FCM/APNs/WNS were unreachable from this sandbox; the encryption and headers were proven against a local stand-in. TASK-043's WNS acceptance (VF28) remains the only real-service evidence. Phones still need a domain (HTTPS).
  • The consent gate is UI-only. The API does not refuse a signed-in viewer who has not consented; a client that skips the React app is not stopped. The gate was not seen in a browser at all — demo mode has no signed-in identity and Supabase was not running here.
  • The app consent notice is a draft, English only, not reviewed by FreshNow or counsel (A-T44.1).
  • Attachments stay Telegram-only. They are Telegram file references; an app-only assignee is told the files are in Telegram but cannot open them. Storing bytes is a separate decision (storage, retention, scanning).
  • The bot still answers inbound messages in App-only mode. The switch stops outbound Telegram messages; whether the bot should also refuse new updates when the company has left Telegram is a company decision not yet taken.
  • Withdraw in the app was tested through the API, not clicked in a browser.
  • Every Azure price in the new deck is an estimate (A-T44.3); the recommended server size is unmeasured (A-T44.2); the recovery time is a target, not a rehearsal.
  • The deck re-check rests on search results except AWS prices. AWS's UAE status comes from press reports of its dashboard.
  • CI has not run with the new workflow — it triggers on pushes to main and on pull requests, neither of which happened.
