One-sentence summary: FreshNow now runs on Supabase, every row copied and counted, and the dashboard has real sign-in — and signing in through a real browser found three defects that the build, the typecheck and 210 tests had all passed.

1 · Why this task

You asked for Supabase as "the final one which will be used when deployed". TASK-024 recommended it for a second reason: the dashboard had no authentication. It decided who you were from ?viewer= — a URL parameter anyone could set to ceo. Row-level security then correctly enforced an identity nobody had checked. Supabase Auth supplies the missing half: an identity the server can verify.

2 · Research

The stack research was done in TASK-024 (Supabase, Supavisor transaction pooling, why our set_config(…, true) RLS context is pooler-safe). This task verified the specifics against the running stack rather than re-searching them:

  • The Supabase CLI (2.117) local stack publishes an ES256 signing key at /auth/v1/.well-known/jwks.json. Local development therefore exercises the same asymmetric verification a hosted project uses — not the legacy shared HS256 secret.
  • New-style keys: sb_publishable_… (public, ships to browsers) and sb_secret_… (bypasses RLS through the Data API). The publishable key works with Auth through the local gateway.
  • On Supabase, postgres has BYPASSRLS but is not a superuser, and is allowed to set session_replication_role — what Supabase's own restore guide uses.

5 · What only a real browser found

Everything above passed its tests. Then a headless Edge, driven over the DevTools protocol, signed in through the actual login form — and found three defects in a row:

G57 — a blank page

Vite built asset URLs from /; the API serves the app at /app/. The page loaded, returned 200, and then 404'd on its own script. Fixed with base: "/app/".

G58 — an employee saw 0 of their 6 assignments

The query joined employee to name who gave the work. Hemanth may not read the CEO's row, so the inner join matched nothing and every assignment the CEO gave him disappeared — with no error. Fixed with the narrow name function in migration 0008, plus a regression test that also proves the employee still cannot list other employees.

G59 — the title and the Ask answer were invisible

A theme colour named base made Tailwind compile text-base as a colour — the background colour. My first diagnosis (a missing CSS variable) was wrong: the built CSS showed the variable was there; the rule for .text-base showed the real cause. Renamed the colour; the check now asserts the title's computed colour and the answer's.

What we have not verified

  • Sign-in from a phone. Port 54321 answered on this PC's Wi-Fi address from this PC. No phone has tried; Windows Firewall may block it for other devices (A-T25.3).
  • A hosted Supabase project. Everything ran on the local CLI stack. The transaction pooler (Supavisor) was excluded locally, so pooled connections are untested (A-T25.2).
  • A real bot conversation since the switch. The bot started and polls on Supabase, but no one has sent it a message since. Telegram reachability on this Wi-Fi is intermittent (G60).
  • Session refresh past one hour in an open browser — supabase-js is configured to do it; it was not watched happening.
  • Signing-key rotation (G61) and password recovery — there is no reset UI, no email service, and the account emails are placeholders (A-T25.1).
  • Supabase's security advisors were not run. Known findings to expect: vector installed in public; RLS off on schema_migrations (it has no anon grants).
  • Per-viewer scoping of the question box's generated SQL is still not built; it is CEO-only instead.

Security

  • The local stack uses Supabase's well-known development keys and JWT secret. They are fine on this PC and must never reach production; a hosted project issues its own.
  • The secret key is in .env (git-ignored) and read only by pnpm link:user. On a hosted project, also switch off the Data API or remove public from its exposed schemas — 0007 revokes the grants, but one control is not two.
  • Dashboard passwords were printed once to the terminal and shared in chat. Change them before anyone else sees the dashboard (pnpm link:user … <new-password>).
  • Still outstanding from earlier: rotate every API key pasted into chat or stored in models/*.txt (Groq, NVIDIA, OpenRouter).
