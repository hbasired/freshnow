One-sentence summary: Every file anyone sends is now checked when it arrives — true type, dangerous names, a ClamAV virus scan, PDF active content — and PDFs are opened in a sealed child process with a memory and time limit; every page carries browser rules that stop injected scripts from running or sending data anywhere; password guessing is braked per phone; backups are checksummed, encrypted, restore-tested and meant to sit offline; and the dependencies and git history are scanned by pinned open-source tools — with production refusing to start without a virus scanner.

Research (30 Sep)

  • ClamAV's daemon scans a byte stream with the INSTREAM command: length-prefixed chunks, a zero-length terminator, answer stream: OK or <signature> FOUND — ClamAV documentation [believed — through search; the protocol was then verified against a real clamd 1.5.4 here]. The official Docker image and its environment variables: docs.clamav.net — Docker, Cisco-Talos/clamav-docker. Sources disagreed on whether CLAMD_CONF_* overrides work in the official image, so none is used.
  • OWASP treats antivirus as one control among several for uploads (new malware evades signatures) — OWASP File Upload cheat sheet [believed — through search]. HTTP headers per the OWASP HTTP Headers cheat sheet and, for JSON, the REST Security cheat sheet (frame-ancestors 'none').
  • PDF.js CVE-2024-4367 — script execution through font handling when isEvalSupported is on, fixed in 4.2.67 (NVD) [believed]. The PDF.js version bundled by unpdf 1.8.1 could not be read from the bundle, so the workaround is applied regardless.
  • Cloudflare passes the visitor's address in CF-Connecting-IP; X-Forwarded-For can be written by the client (http.dev, cloudflared #1426) — so the header is believed only from this machine.
  • Trivy's own releases were compromised in March 2026 (0.69.4; Docker images 0.69.5–0.69.6), 0.69.3 named the last clean release — GHSA-69fq-xp46-6x23, Docker's note, StepSecurity. This changed the design: pinned images, an isolated read-only clone, no network for gitleaks.
  • gitleaks v8.19+ replaced detect with git/dir; latest v8.30.1 (gitleaks). OSV-Scanner v2 scan source -r, reads pnpm-lock.yaml (usage, releases).
  • UAE PDPL requires security measures appropriate to the risk, including restoring access to personal data after a failure — search summaries of the law (Securiti, Modulos) [believed; article number (20) to confirm on the text]. This is why R6 now requires a scanner in production.
  • CISA's ransomware guidance: offline, encrypted, tested backups [believed — through search]; "3-2-1-1-0" is an industry shorthand, not CISA's term.

What was built, layer by layer

1 · Files. scanBytes (clamd INSTREAM, never throws) runs inside inspectFile after size/name/type and before any parser. Infected → refused, audited security.malware_blocked; scanner configured but down → refused security.scan_failed (fail closed). Both count toward the document rate limit. extractPdfTextSandboxed runs PDF.js in a child Node process with --max-old-space-size, a kill timer, an output cap and an environment holding nothing but its own settings. Documents sent in Telegram now pass the gate on arrival (gateIncomingDocument), and saveAttachments will not store a file marked not-forwardable — one chokepoint for every path.
2 · Browser and API. security-headers.ts sets the headers on every response and a strict CSP on the app, with the inline theme script allowed by its SHA-256 (computed from the built index.html at start-up). The auth proxy brakes password guessing per device. The service worker opens only same-origin /app URLs from a notification.
3 · Recovery and supply chain. pnpm backup / backup:verify / backup:restore-test; pnpm security:scan; ClamAV as an opt-in compose profile; /health reports antivirus; the Compliance page shows scanner, last backup, restore test and sign-in pauses; the daily snapshot records them. Policy rule R6 requires CLAMAV_HOST in production.

Decisions and why

  • No new runtime dependency. The clamd protocol is 40 lines; the headers are a dozen strings; the backup and scan tools are open-source binaries run as processes. (Dev: nodemailer and vitest upgraded to fix advisories.)
  • Fail closed once a scanner is configured — otherwise stopping ClamAV would be the bypass. The demo default stays "not configured", so the laptop demo works as before.
  • A process, not a worker thread, for the PDF sandbox — the thread's memory limit was measured not to hold (G128).
  • Photos are not scanned — Telegram re-encodes them; documents (including images sent as files) are.
  • nodemailer 10.0.12, not 10.0.13 — the newer one was inside pnpm's one-day quarantine; the older one has every fix. No exclusion was kept (G130).
  • In-memory sign-in counts — a restart forgets; accepted for a brake, and it stores no addresses.

How it was verified

  • Unit + integration tests written from the rules: a stand-in clamd that checks the wire protocol byte for byte, chunking over 64 KB, timeouts, fail-closed, the gate's audit rows; a real ClamAV 1.5.4 refusing EICAR and passing a clean file; the sandbox reading a real PDF, refusing 60 pages, killing a slow run, aborting a 16 MB-heap run, and failing cleanly on garbage; the arrival gate (malware refused, too large and download failure refused, clean held, active content held but never stored as an attachment); headers and CSP (the hash checked against the CSP specification's published example); the sign-in brake (per device, tunnel header only from loopback, success clears, refresh not counted); R6; the Compliance security evidence.
  • Live: an EICAR upload through the running API was refused and audited; a clean one passed the scanner. /health shows "antivirus":"ok".
  • Chromium (Playwright): 37/37 UI and 13/13 compliance checks with the CSP on, no console errors; injected inline script, inline handler, eval and new Function from a page script, and a fetch to another origin were all refused.
  • Backups: plain and age-encrypted dumps restore-tested (counts equal the manifest); restore test refuses an encrypted file without the key; one changed byte fails the checksum; pruning keeps N.
  • pnpm security:scan: passes; a staged .env.production made it fail with exit 1. pnpm audit (all dependencies): clean.

What we have not verified

  • ClamAV with its real signature database. Signature downloads were blocked here; the real-scanner test used a local EICAR signature. The official image, its first start and its memory use on the laptop are not observed.
  • The container scanners (gitleaks, OSV-Scanner, Trivy) — no Docker daemon here. Image tags come from release notes and are assumed to exist (A-T51.1).
  • The backup script's Docker path (pg_dump inside supabase_db_freshnow, restore into the Supabase cluster, where extensions may produce warnings). Only the local pg_dump path against Postgres 16 was run. winget install FiloSottile.age and robocopy are not run here.
  • The CSP through the Cloudflare tunnel on a real phone, and whether cloudflared sends X-Forwarded-Proto (A-T51.3). Nothing Cloudflare might inject is allowed to run — if it tried, it would show as console errors, not a broken page.
  • The Telegram arrival gate against real Telegram — download failures and large files were tested with injected downloads, not the Bot API.
  • The PDF.js version bundled by unpdf — the CVE workaround is applied regardless. The sandbox is not an OS jail.
  • Legal reading: that PDPL Art. 20 is the security article; that R6's scanner requirement is what a regulator would expect.
  • The 9 model-dependent tests — no route to a model provider here; they need a real key on the laptop.
