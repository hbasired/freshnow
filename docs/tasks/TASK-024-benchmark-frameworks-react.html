1 · The benchmark

A generic benchmark tells you which model writes prose fast. It does not tell you which model can read romanised Hindi, refuse to invent an employee, or resist a prompt injection — which is all this system ever asks a model to do. So scripts/bench-models.ts uses five real prompts, graded by the same deterministic checks the system itself applies.

The result that settles the local-model question

qwen2.5:0.5b is the tempting one — free, on CPU, 55 tok/s. It failed to recognise a Malayalam message saying the machine had stopped and juice could not be made, and mis-categorised the Hindi chiller failure as "supply".

In a chatbot that is a quality score. Here it is a worker reporting a breakdown and nobody hearing. Latency is not the axis that matters for this system; a fast wrong answer is worse than a slow right one.

Incidental findings worth acting on

  • llama-3.3-70b-versatile now returns 404 — decommissioned. A benchmark against a docs page would have missed this; querying /v1/models caught it.
  • Groq's live catalogue includes meta-llama/llama-prompt-guard-2-{22m,86m} — a dedicated prompt-injection classifier. Worth evaluating against the 14 rule-based patterns added in TASK-021, which are explicitly a tripwire and explicitly English-centric.
  • Context is not a constraint. Groq gives 131 072 tokens; the largest prompt this system builds is under 8 000. About 16× headroom, so context window should not drive model choice.

The benchmark found a real defect in our own configuration

TASK-022 set the concurrency limiter to 6 simultaneous model calls, sized from this box's 8 vCPU. That was the wrong constraint. A document plan costs up to ~2 350 tokens, so six at once is ~14 000 tokens against an 8 000/minute budget — 1.8× over. The client had no 429 handling, so it burned both retries in milliseconds, fell through to OpenRouter (401) and NVIDIA (503, then timeout), and the whole call failed. It took out a full test run while this report was being written.

Fixed: concurrency lowered to 2; LlmRateLimitError distinguishes a rate limit from a broken provider; the client waits the provider's own reset hint, capped at 30 s.

There is currently no working fallback provider

OpenRouter returns 401 User not found; NVIDIA returns 503 then times out. The independent fallback the design depends on does not presently exist. Fixing the OpenRouter key is the highest-value operational action outstanding.

2 · The three frameworks — three different answers

They are marketed as a stack and are independent decisions.

VerdictReason
LangChainNo Its value is a provider interface plus structured output and tool plumbing. llm/client.ts already is that in ~200 lines, and every line exists because of a failure we hit.
LangGraphNo Its central feature is model-driven control flow. CLAUDE.md rule 3 forbids exactly that in writing. Everything it is recommended for, this system already does deterministically. It is also Python while the bot is Node.
LangfuseYes Framework-agnostic — its TS SDK is a thin OpenTelemetry layer that works with a plain OpenAI-compatible call. Fixes llm_call.cost_usd reporting 0, adds nested traces, and brings the prompt-versioning and datasets that CLAUDE.md's "contract tests on every prompt change" actually needs.

3 · Agentic tool-calling, and what it would cost

Measured industry figures: 3–5× tokens for a simple agent loop, 5–30× typical, 50–100×+ multi-agent — because every step re-sends the accumulated context and tool definitions.

Every model call in FreshNow today is a single-shot extraction: text in, one validated JSON object out. There is nothing to iterate on — the context is retrieved deterministically before the call. Wrapping a ~600-token status extraction in a four-tool loop makes it ~2 500 tokens to produce the identical JSON.

The exception is the CEO's question box. "Why is Priya behind this week?" genuinely needs a lookup, then a decision about what to look at next. That loop is already half-built — bounded at 8 iterations, read-only guard, row cap, numeric-sanity and grounding gates. What would improve it is more tools, not more framework: get_employee_context, get_task_history, search_notes over the pgvector extension that is installed and unused. Native tool calling on the existing endpoint handles the loop.

4 · The stack: Supabase yes, React yes, FastAPI not now

Supabase — do it. Supabase is Postgres: schema, all six migrations and every RLS policy move essentially unchanged, and it closes the largest open gap — the dashboard has no authentication at all. A decision made months ago turns out to be exactly what it requires: Supavisor pools in transaction mode, and this system already sets RLS context with set_config(..., is_local => true) rather than a plain SET, written to stop a pooler leaking one user's context into another's.

FastAPI — not now. ~7 000 lines carrying 200 tests, 57 recorded decisions and 55 gotchas, each a bug someone hit. A rewrite re-discovers all fifty. The bot cannot move — grammY and the concurrency work are Node — so it means operating two runtimes rather than replacing one. The usual reason to want Python here is the LangChain/LangGraph ecosystem, and the recommendation is not to adopt those. If there is another reason, it should be stated rather than assumed.

What we have not verified

  • Nobody has opened the React dashboard in a browser. Verified by build, typecheck and HTTP status only. The viewer selector, date picker, row expansion, EOD generation and Ask box have not been clicked, on a phone or otherwise.
  • One benchmark sample per cell. This measures correctness, so each task ran once per model. A 5/5 is encouraging, not a guarantee — it cannot separate "reliable" from "lucky".
  • Local latency is a CPU result — no GPU is passed through to the Ollama container. The accuracy column is hardware-independent; the latency column is not.
  • Local models were not given the two long tasks (minutes each at ~10 tok/s), so their scores cover blocker extraction only and are not comparable to a hosted 5/5.
  • A second benchmark pass was still running when this was written, covering qwen3.6-27b, qwen3.8-27b, groq/compound-mini and all six NVIDIA models with a longer timeout. Re-run pnpm bench:report to fold it in.
  • Nothing here has been migrated to Supabase. The recommendation is researched, not executed.
  • Langfuse is recommended, not installed.
  • Prices are list prices entered by hand, not read from an API.

Security

The OpenRouter key supplied returns 401 User not found — dead, and the same key that failed in the earlier session.
