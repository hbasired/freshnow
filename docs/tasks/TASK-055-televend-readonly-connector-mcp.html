Why it was done this way

An allow-list, not "only send GET"

The account we were given is a Televend CompanyManager: its own permission list (read from Televend's access-control service) shows edit rights on machines, events, products, prices, routes and more. "We will only call GET" is not enough either — Televend's web app has GET endpoints that start things (GET …/vend/v1/{company}/export/{format} starts an export job that can e-mail its result). So every request must match an exact host + method + path rule written in allowlist.ts; anything else throws TelevendRefusedError before a token is even requested. Widening the list takes a code change and a test, never a setting. Every write found in Televend's specs and bundles is listed in allowlist.test.ts and refused.

Three transports behind one interface

  • Bridge (chosen by the user until Televend issues API credentials) — the GET calls Televend's own web app makes, signed in as a web user. Undocumented, so it may change; the research ranks it below the official API, which is why the connector is built to switch.
  • Official — Televend's documented Data-Streaming API (Keycloak client credentials; fetch → persist → commit). Built against the published specs and tested with a stub; no credentials exist yet.
  • Files — the XLS/CSV exports people already download, for history and as a fallback.

Account safety

Keycloak counts failed passwords. The connector signs in once, lives on the refresh token, and on a refused credential stops for good (latched) — it never retries a password. Retries for everything else are bounded, and a circuit breaker pauses calls after repeated failures.

Why the MCP server computes the answers

CLAUDE.md rule 2: the model never counts or sums. A tool returns totals computed in TypeScript plus at most 50 rows as evidence, and says truncated/complete whenever something was cut. Filler names are personal data and the model's context is a processor of whatever is put in it, so they default to initials.

r(`official.stream.commit@${host}`, host, "POST", `/televend-api/data-streaming/${SLUG}/api/v1/offsets`, "offset-commit"),  // off by default

Windowed reads instead of paging (the drift fix)

Vends and events are read by time window. A window is asked for as one page of 100; if Televend says there is another page, the window is split in half and each half asked again, until every slice fits in one page. Rows are de-duplicated by Televend id, so slice edges that Televend treats as inclusive cannot double-count. Bounded at 600 requests and a one-second minimum slice; a result that hit a bound says complete: false.

Refills are per machine

Televend's refill log answers one machine and one day per request (date must carry a time zone). The MCP tool reads all enabled machines for a past day (about 90 paced requests); the sync job (TASK-056) will ask only for machines whose last_refill moved.

Concepts and techniques used

  • Allow-list (default deny) at the egress point — the same idea as RLS default-deny, applied to outbound HTTP: a request is refused unless a rule says yes, and the rule set is code under test.
  • Canonical-form check — the URL parser silently resolves .., %2e%2e and backslashes; the gate refuses any URL whose sent path differs from the written one, so nothing can walk out of an allowed prefix.
  • Latching credential failure — a circuit that never closes on its own for the one error that can lock an account.
  • Circuit breaker, bounded exponential backoff, Retry-After — CLAUDE.md rule 4 applied to an external API.
  • At-least-once stream consumption — fetch → persist durably → commit; a crash between the last two re-delivers, and unique keys absorb it.
  • Adaptive time slicing — replaces offset paging, which is unsafe on a list that changes while it is read.
  • Transport-agnostic normalisation — downstream code sees TvMachine/TvVend/TvEvent/TvRefill, never Televend's JSON.
  • Synthetic fixtures with real layouts — test files generated in memory with SheetJS, so the public repo never holds company data.

Research findings (web search and live probes, 15 Oct 2026)

  • Televend has an official API (devportal.televendcloud.com): Gravitee + Keycloak, JWT client credentials (2 h), Data-Streaming (vends, vending-events, fill-events, cash-collections, cashbag-countings, …; offset-based; 7-day retention), Master Data (GET /importer/{type}/api/v1; its upsert/delete are writes), Operational, Wallet. Credentials come from Televend IT onboarding; price not published. The commit is POST …/offsets with no body (spec v1.9.0).
  • The web app (Angular 21 micro-frontends, app 4.8.3) calls api-cloud.televendcloud.com/{machinist, cashtrack, warden, refillator, reportforge} and an older FastAPI host; {tenant_id} is 5 for this company.
  • MCP SDK: @modelcontextprotocol/server 2.3.1 is the v2 "stable release line" (npm, 2026-10-15); it depends only on its core and zod ≥ 4.2, negotiates protocol versions back to 2024-10-07 (read in the package), and serves stdio with serveStdio(). Chosen over v1 @modelcontextprotocol/sdk 1.32.1, which pulls in express, hono, ajv and more.
  • SheetJS: the npm registry copy is stuck at 0.18.5; the vendor publishes on its CDN (0.20.3, Apache-2.0). OSV lists CVE-2023-30533 and CVE-2024-22363 for "xlsx" with no fixed npm version, but the advisories state fixes in 0.19.3 and 0.20.2 — 0.20.3 is past both. pnpm audit reports nothing for the CDN dependency.
  • Comparable systems (research for the plan): Cantaloupe, Parlevel/365 and Nayax VMS all derive expected cash from machine meters and reconcile per driver per service — the pattern TASK-062 will use with Televend's data.

What we have not verified

  • Cash amounts: this account cannot see the cash centre (403) nor vend values (hidden). Whether Televend's cash-collection records carry the machine's counted/expected cash is believed from the specs (cashIncome, cashLeftInMachine), not seen.
  • Refill fill_type 2 ("removed") and source 3 ("Televend") meanings — not seen in live data; they stay "unknown" if they appear.
  • That the export files' local times are Asia/Dubai — consistent with every match made (minute-level), but not documented by Televend.
  • Long-run behaviour: token renewal over a full Keycloak session, the circuit breaker against a real outage, Televend rate limits (not published).
  • Claude Code picking the server up from .mcp.json on another machine — tested here by driving stdio directly.
