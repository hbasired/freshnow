How it was done

  • Service worker on load. registerWorker() runs in main.tsx before React renders, on secure pages only. The worker's new fetch handler touches page loads only and answers them from the network: no cache, keeping the rule that the board is always a live count. Data calls, the live stream and sign-in never reach respondWith.
  • Install button. lib/install.ts keeps the browser's beforeinstallprompt from the moment the page loads. It exposes an install state: installed, available, iPhone, use-the-menu, or not secure. The device card explains each state; the header button appears only when one tap can install.
  • "Does it behave like a normal app?" For messages, yes. Once installed and switched on, notifications arrive with the app closed, through the phone's normal notification settings, and a tap opens the right task. They stop while the laptop, which is the server, sleeps or the tunnel stops.

What we have not verified

  • A real Android phone after this change. Everything above ran in desktop Chromium emulating a phone. Whether Chrome on Android now installs a full app rather than a shortcut rests on Chrome's published guidance, not on a device.
  • Brave on Android: whether it fires the install event or delivers web push at all. G121 is based on search results, and the guide steers to Chrome.
  • Battery optimisation on Samsung phones delaying notifications. The guide's tip to set Chrome's battery use to Unrestricted is general advice, not observed on this system.
  • A real notification on a real phone is still the first thing to confirm, with "Send a test notification" once Chrome is installed.
