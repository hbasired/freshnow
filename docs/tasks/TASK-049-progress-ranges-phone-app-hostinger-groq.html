2 · Progress as a range

  • Why a range is the honest input. A person's estimate is a range; a typed "15%" claims a precision nobody measured. So the range is stored as given (task.progress_band_low/high, progress_event.band_low/high) and shown as given: "20–30%", with a bar that is solid to 20 and lighter to 30.
  • One number for arithmetic. progress_pct still holds one number because project rollups and the "behind" flag are sums over it. For a range it is the midpoint (0–10 → 5, 90–100 → 95): the value that neither flatters nor punishes an estimate when nothing says where in the range the work sits. The task page says so: "a range, counted as 25% in totals". A choice, not a standard; recorded as D146.
  • One list, checked twice. PROGRESS_BANDS in core is the rule; the API refuses any other range with a 400 (Zod) and core refuses it again; the database refuses a range on a figure nobody picked, or a number outside its range (CHECK constraints). A test reads the dashboard's list from its source and fails if it drifts from core's.
  • No 100% range. "90–100%" is the top. Finished is reported with ✅ Done, which moves the status and makes it 100% by status.
  • Evidence still wins. Ticking a step recomputes from the count and clears the range (existing rule D77, extended).
  • "I know the exact number…" stays in the list for the rare person who has one.

4 · The phone app

The old phone view was the desktop page with the sidebar turned into a 4×3 grid of buttons, the six count tiles repeated on every page, and wide tables scrolling sideways. Now, below 1024 px:

  • A tab bar at the bottom — Home · My work · Assign (or Projects, for people who cannot give work out) · Alerts · More — with badges for open tasks and urgent problems. More holds every other page as a large row with what it is for, a search over everything on the board, and this device's settings (theme, install, refresh, sign out, and the demo "see as" picker).
  • A title bar — the page's name, the live status, the attention button and the inbox bell. A page reached from More, or a project, has a ‹ back arrow.
  • One layout mounted, not two hidden. useMedia picks the layout on the first paint; hiding one copy with CSS would have mounted two inbox bells fetching the same notifications (D148).
  • Tables become cards below 640 px, in DataTable, so every list on every page changed at once (D149).
  • The counts live on Home only, three across. "Needs a human" comes before the week chart. A day switcher (‹ date ›, Today) replaces the header's date field.
  • A task is its own page on the phone, with ‹ Back, a sticky header, and room for the safe areas of phones with notches.
  • Back goes back. The URL hash was only ever replaced, so a phone's back gesture left the app. Each page change now pushes a history entry (the first sync still replaces, so a shared link adds none), an open task is an entry of its own, and popstate makes the URL the truth: Back closes the task first, then steps back a page (D150).
  • The desktop layout is unchanged except for the new pickers and chips.

Concepts and techniques

  • Interval input, point storage. Store what the person said (the interval) and derive the number arithmetic needs (the midpoint), labelling the derived number as derived. The same idea as D89, where a person's claimed percentage sits beside the computed one.
  • Defence in depth for one list. The same allowed set enforced at the API schema, in core, and as a database constraint, plus a test that the browser's copy matches.
  • Mobile navigation pattern. A bottom tab bar for the few daily destinations plus an overflow page is the pattern the major phone platforms document for top-level navigation [believed — Material Design and Apple HIG describe tab bars; not re-read this session].

What we have not verified

  • A real phone. Every phone check ran in desktop Chromium emulating a 390 px touch screen. Safe-area padding on a notched iPhone, Android's back gesture in an installed app (tested as browser Back in Chromium), and the native date and select pickers on a device are unobserved.
  • Whether employees find it easier. The layout follows the owner's description of what was confusing; nobody who does the work has used it. The starter phrases are English only — Hindi, Malayalam and Urdu versions need a native speaker, and whether the blocker parser classifies each starter well was not measured (no live model in this container).
  • The midpoint choice is a judgement (D146). If FreshNow prefers ranges to count conservatively (the low end) for the "behind" flag, it is one function to change.
  • The Telegram bot has no progress input, so ranges exist in the dashboard and the phone app only.
  • All research findings rest on search summaries; no primary page opened (network policy). The Hostinger DPA's exact wording, whether it covers a UAE customer, where VPS backups live, whether Groq's ZDR can be set per request, and OpenRouter's enterprise-only DPA should each be read on the page itself before relying on them.
