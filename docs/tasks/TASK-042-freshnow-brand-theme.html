TASK-042 — FreshNow's own green and orange, applied without breaking readability

2026-09-19 · no migration, no API change · dashboard tokens, hero band, branded entry screens · 376 tests green (unchanged — this is presentation)

One-sentence summary: The dashboard now wears the company's colours, sampled pixel-by-pixel from the FreshNow website rather than guessed — used as fills where they are beautiful and as darkened steps where they have to be read, because the brand greens fail contrast as text by a factor of three.

2 · The problem with brand colours in a dashboard, and what was done about it

All three brand colours are unreadable as text. Measured: white on #97d700 is 1.74:1, on #9bca3c 1.93:1, on #f39c12 2.19:1 — against the 4.5:1 that body text needs. The website uses white on green in its header, which is fine for a marketing page nobody reads for eight hours; it is not fine for an operations screen.

But the same colours are excellent as fills with dark ink: near-black on them measures 8.6–10.9:1. So the rule for this theme is: brand colours are fills, never text, and the ink on them is near-black in both themes — a brand fill is the same green on a light page and a dark one, so the text on it must be too.

Where the colours have to be read — a number on a card, a label, a chart bar — the same hues were stepped until they passed, and every step was measured against every surface it actually lands on:

3 · The chart: where the brand had to stop

The obvious move was green + orange bars — the brand's two colours. The data-viz validator refused it. Brand green beside brand orange measures ΔE 0.4–3.6 under simulated red-green colour blindness, against a floor of 8: a colourblind reader would not be able to tell "completed" from "pending" at all. Three variations were tried and all three failed.

So the chart keeps green / blue / red, with the green stepped into the validator's lightness band (#3d6b10 light, #6ea329 dark — both pass all six checks). The brand carries the chrome; the chart carries the meaning. That boundary is now written into index.css so the next person does not undo it.

A second finding from the same measurements, worth recording because it predates this task: in light mode warn and crit have never cleared the separation floor — the shipped #7d4e00 vs #a40e26 measured ΔE 13.4 (normal vision) and 1.7 (deutan). The brand orange #9d5404 is better on both counts, and every status in this app already ships with an icon and a word beside it, which is the documented mitigation. It is an improvement on the old palette, not a new problem.

What we have not verified

  • The three hexes are sampled from a screenshot, not from a brand guide. They are exact pixel values of what the website renders, which is not the same as what the company's designer would call the brand colours. If a guide exists, replace the three --color-brand* / --color-accent values and re-run the contrast pass — nothing else needs to change.
  • Nobody has seen this on a real monitor yet — only headless screenshots at 1440×1000 and 390×844. Colour on a phone in Dubai daylight is a different question from colour in a virtual framebuffer.
  • No colourblind person has looked at it. The validator simulates protan/deutan/tritan; that is a model, not a user.
  • The citrus slice is my drawing, not the brand's asset. If FreshNow has the real artwork, it would be better.
  • Only the Overview got the hero. The Projects portal still opens on its own plainer header.
  • The old KPI screenshot in TASK-041 is now out of date — that document describes the structure, which has not changed, but its colours in any future screenshot will differ.
