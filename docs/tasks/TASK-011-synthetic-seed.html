What was done

  • packages/core/src/seed.ts — seedDemo(): idempotent, inserts 5 DEMO – employees (warehouse, production, delivery, retail, QC; English + Hindi), 6 tasks, 6 past updates (done/pending/blocker across a few days), and 3 blockers — routed through the real engine (so audit history is genuine), one escalated, plus run_trace rows for replay.
  • scripts/seed.ts + pnpm seed — seeds the demo database.
  • Test — runs seedDemo twice, asserts identical counts (idempotent) and is_synthetic=true on every seeded row.

Why it was done

The company has not shared real employee data yet. To demonstrate the working system end-to-end, the demo needs history — but that history must never be mistaken for real. So every seeded name is DEMO – prefixed, every row is is_synthetic=true, and the blockers are routed/escalated by the same deterministic engine the live system uses, so the audit trail and traces are authentic even though the data is invented.

How it works

seedDemo()  (idempotent)
  delete prior seed (fixed employee ids + seed correlation)
  upsert 5 DEMO employees (report to CEO)
  insert tasks + a few days of updates (done / pending / blocker)
  insert 3 blockers → routeBlocker() → assigned_resolver=CEO, SLA, audit
  make one overdue → escalateBlocker() → escalation + alert + audit
  insert run_trace rows (for replay)
  → { employees:5, tasks:6, updates:6, blockers:3 }

Concepts and techniques used

  • Idempotent seeding — fixed ids + a seed correlation id; a re-run wipes and re-inserts, never duplicates.
  • Labelled synthetic data — DEMO – names + is_synthetic everywhere; the honesty rule made concrete.
  • Exercising the real pipeline — blockers go through the actual routeBlocker/escalateBlocker, so the demo's audit/trace history is genuine.

What we have not verified

  • Every name, role, site, and shift is invented — none reflect real FreshNow staff or operations. All are [assumed].
  • The volume is tiny (5 employees, a few days) — enough to demo, not to benchmark.
  • The seeded note_parsed is hand-written to match plausible LLM output; the parser was not re-run over the seeded note_raw.
  • The seed is designed for the demo DB; running it replaces prior seed data (not additive).
