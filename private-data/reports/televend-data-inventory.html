Things to know about Televend’s data

  • Daily totals: Televend’s sales counter ignores the time of day — asking for 06:00–07:00 returns the whole day. The system only uses it for whole days.
  • Long lists can shift while being read: reading one 23-hour list twice gave 95 duplicates and 95 missing rows. The system reads in small time slices instead — re-reads now match exactly.
  • Machines get renamed: 9 of the 87 enabled machines changed name between 13 and 15 Oct. The machine number (e.g. 543) stays — the system keys on it.
  • A machine that moves keeps its old record: Televend gives a moved machine a new record and switches the old one off. The old record still holds its refills — including the machine being emptied before the move — but no longer shows a “last refill”. Machine 393 moved on 6 Oct; its rows of 4 and 6 Oct were only on the old record. The system now reads every record, switched off or not, for past days.
  • Two refills in the same second can both be real: a two-juice machine logs one per column. The system tells them apart by column (11 Oct: one machine, columns 511 and 767, 3 cups each).
  • Some alarms show “resolved” before they started (repeating alarms). Shown as a note, never as a negative time.
  • Typed WhatsApp posts carry mistakes (“Naif 318” was machine 319). Scanning the machine’s QR code in the new app removes this.

How to use it

  • In Claude Code (this project): the freshnow-televend tools — status, machines, sales on a day, alarms on a day, refills on a day, cash collections on a day.
  • pnpm televend:sync — read what is new (the worker does this every 10 minutes); pnpm televend:backfill --from 2026-09-01 --to 2026-10-14 — load history.
  • pnpm televend:verify --day 2026-10-12 — compare a day with the exports in data-televend.
