=====decisions.md
## D179 — The user directed the Operations + Inventory expansion now (TASK-055) [verified — user decision 2026-10-15]
Operations and Inventory portals, a read-only Televend connector (MCP + pipeline), a Flutter Android staff app, a built-in chat that
replaces the WhatsApp groups, and eight new roles — ahead of the Phase 3/4 table in CLAUDE.md. This supersedes CHANNELS-GUIDE's
"drivers stay on Telegram" and the Driver-PWA plan (TASK-BOARD 042); the messaging-resilience report's objection to a separate chat
server still holds (chat is built inside our own API and database). Telegram and email stay. The approved plan is recorded in the
TASK-055 write-up; tasks 055–069 follow it one at a time.

## D180 — One Televend client, one egress gate: an allow-list of host + method + path (TASK-055) [verified — tests + live runs]
Every request to Televend goes through `TelevendClient`, which calls `decide()` (packages/televend/src/allowlist.ts) before
asking for a token or touching the network. A method check alone is not enough: Televend's web app has GET endpoints that START
export jobs. Widening the list takes a code change and a test, never a setting. Rejected: trusting the account's permissions (the
account given to us can edit machines, prices and events).

## D181 — A refused Televend credential latches; the password is never retried (TASK-055) [verified — tests]
Keycloak counts failed passwords. `PasswordSession` signs in once, lives on the refresh token, and after a refused password (or a
refused API client) throws `TelevendAuthError` for every later call until the process restarts with new settings. A 5xx from the
token endpoint is not a refusal and does not latch.

## D182 — Three Televend transports behind one interface; the bridge until the official API exists (TASK-055) [verified — user choice + tests]
`TelevendSource` = bridge (the web app's own GETs, chosen by the user 2026-10-15), official (documented Data-Streaming API, fetch →
persist → commit), files (portal exports). Downstream code sees normalised `Tv*` rows only, so switching transports changes nothing
downstream. The bridge is to be replaced by the official API as soon as Televend IT issues a read-only client.

## D183 — Windowed reads with adaptive slicing instead of offset paging (TASK-055) [verified — live re-read]
Televend's paging drifts on large windows (G148). Vends and events are read as time slices that each fit one page; a full page splits
the slice in half. Bounded (600 requests, 1-second minimum slice) and honest (`complete: false` when a bound is hit).

## D184 — MCP over the v2 SDK, answers computed in code, names as initials (TASK-055) [verified — stdio run]
`@modelcontextprotocol/server` 2.3.1 (v2 "stable release line": two dependencies) over v1 `@modelcontextprotocol/sdk` 1.32.1
(express, hono, ajv…). zod 4 is installed for the MCP package only; the rest of the repo stays on zod 3. Every tool returns totals
computed in TypeScript plus at most 50 rows; filler names default to initials because the model's context processes whatever we
put in it (CLAUDE.md rules 2 and 4; minimum-necessary prompts).

## D185 — SheetJS 0.20.3 from the vendor CDN, pinned by sha512 (TASK-055) [verified — install + parse of 11 real exports]
Needed for the portal's legacy `.xls` event exports. The npm registry copy is stuck at 0.18.5 (affected by CVE-2023-30533 and
CVE-2024-22363); 0.20.3 is past both fixes. Installed from `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`; the lockfile's
integrity hash makes a changed tarball fail the install rather than slip in.

## D186 — Company data never enters the public repository (TASK-055) [verified — git check-ignore]
WhatsApp exports, Televend exports, screenshots and analysis outputs live in git-ignored folders (`private-data/` for everything new).
Tests use synthetic files generated in memory with the real layouts. Committed write-ups give methods and match rates, not sales
figures or names; detailed reports go to `private-data/reports/`.

=====gotchas.md
## G147 — Televend's vend count ignores the time of day and includes the end date [verified 2026-10-15]
`/vends/aggregates` and the vends list's `number_of_items` treat the window as whole dates, inclusive: "12 Oct 06:00–07:00" returned
the whole of 12 Oct; "12 Oct 00:00 → 13 Oct 00:00" returned 12 + 13 Oct (exactly double). The vends LIST respects timestamps. Use
the count only for whole days, with the end sent as the last second of the last day (`BridgeSource.vendTotals`).

## G148 — Televend's offset paging drifts on large windows [verified 2026-10-15]
The same 23-hour event window (≈ 17 pages) read twice: the second read returned 95 duplicate rows and silently skipped 95 events,
including two cash collections. A 3-hour window (2 pages) read identically. Never page across a big window — slice it (D183).

## G149 — Televend request shapes that are not obvious [verified 2026-10-15]
The FastAPI host (`cloud-cloud-web-app…`) answers 400 "Header: x-tenant-id is missing." without the tenant headers. The refill
log is per MACHINE (`refill-log-list/{machine id}/details`), and its `date` must carry a time zone ("Input should have timezone
info"). The access-control list needs the tenant headers too. `machine_search` is a vends filter, not a machines filter.

## G150 — Machine names change; never key on them [verified 2026-10-15]
Between the 13 Oct export and a live read on 15 Oct, 9 of the 87 enabled machines had been renamed ("…-543-DXB" →
"…-543-Cashless 1-DXB"). Match by Televend id, or by the asset number in the name (`assetNumber()`), never by caption.

## G151 — dotenv 17 writes to stdout by default — fatal for a stdio MCP server [verified 2026-10-15]
Any byte on stdout that is not protocol corrupts the MCP stream. Load `.env` with `config({ quiet: true })` and log to stderr only.

## G152 — Scanners flag SheetJS "xlsx" at every version [verified 2026-10-15]
OSV records GHSA-4r6h-8v6p-xvw6 and GHSA-5pgg-2g8v-p4x9 for npm "xlsx" with "introduced: 0" and no fixed version, because the
fixed releases exist only on the vendor CDN. The advisory texts say fixed in 0.19.3 and 0.20.2; we use 0.20.3 (D185). Expect
OSV-Scanner to report it; `pnpm audit` does not (it skips tarball dependencies).

## G153 — SheetJS `blankrows: false` shifts row positions [verified 2026-10-15]
The event export has a blank row above its header; skipping it moved the header into the first nine rows that were read as
metadata, so TYPE became "Name". Locate the header by its column names and read metadata only above it. Caught by files.test.ts.

## G154 — The laptop's real email settings leaked into the test suite [verified 2026-10-15]
`vitest.setup.ts` cleared SUPABASE_* but not SMTP_*/EMAIL_*; with the live Gmail settings (and a two-address EMAIL_ALLOWLIST) in
`.env`, the email suites refused their own test addresses — 5 of the 7 baseline failures. The setup now removes SMTP_*, EMAIL_* and
TELEVEND_* (no test may reach the real Televend).

## G155 — Televend reports some alarms "resolved" before their latest start [verified 2026-10-15]
Repeating alarms (counter > 1): start 23:54, resolved 23:45. Never print a negative duration; show a note instead.

=====verified-facts.md
## VF54 (2026-10-15) — Televend has an official API [verified — devportal.televendcloud.com + its OpenAPI specs]
Gravitee + Keycloak; JWT via OAuth2 client credentials (2 h, no refresh token), issued by Televend IT at onboarding (UAT token URL
`uat-auth…/realms/gravitee3/…`, production URLs given at onboarding). Data-Streaming: vends, vending-events, fill-events,
cash-collections, cashbag-countings and more; `GET …/records` returns `{partition, offset, dataType, data}`; commit is
`POST …/offsets` with no body (204); streams keep 7 days; ≥ 1 request/second for near-real-time APIs. Master Data reads are
`GET /importer/{type}/api/v1`; upsert/delete are writes. Price not published.

## VF55 (2026-10-15) — Programmatic sign-in to the Televend web app works [verified — one sign-in, read-only calls]
Keycloak `auth.televendcloud.com`, realm `televend`, public client `cwa-route-fe`, password grant: access token 600 s, refresh
900 s. The token carries no app roles; Televend checks permissions server-side (`/warden/televendcloud/access-control-list`).
Tenant id for this company: 5.

## VF56 (2026-10-15) — What the account we were given can and cannot do in Televend [verified — its access-control list]
Role CompanyManager with EDIT rights on machines, events, products, prices, routes and more — hence the code-level allow-list.
Cash-centre views are all off (cash collections → 403), vend revenue is hidden (`value: null`), and it cannot view or create users.

## VF57 (2026-10-15) — A live read matches the portal's own exports [verified — pnpm televend:verify, 12 Oct and 5 Oct]
Machines: same total and enabled count (9 renamed, matched by asset number). Refills: 0 per-machine mismatches in rows or cups on
both days. Alarms/warnings: every exported row matched a live event on the same machine and minute (65/65 and 87/87). Vends: the
windowed list equals Televend's whole-day count on both days.

## VF58 (2026-10-15) — Televend code meanings seen in live data [verified — matched against exports]
Event level 3 = alarm, 2 = warning (every exported row), 1 = everything else (info: ORF_* machine codes, "Power OFF", "Cash has
been collected from the machine."). Refill `fill_type` 0 = Filled, 1 = Corrected; `source` 2 = Mobile app, 1 = Web app.

## VF59 (2026-10-15) — Televend's "cash collected" events line up with the WhatsApp cash posts [verified — one night shift]
14 Oct 12:00 → 15 Oct 11:00: 38 of 41 WhatsApp machine posts matched a Televend "Cash has been collected from the machine." event
on the same asset number within 90 minutes (median 1 minute). The one real mismatch was a mistyped machine number in the post;
the two others were a fuel receipt and a deposit photo. Per-person matched totals equal the people's own posted totals. Detailed
analysis (with names) kept in private-data/reports/.

## VF60 (2026-10-15) — MCP TypeScript SDK v2 [verified — npm + package source + stdio run]
`@modelcontextprotocol/server` 2.3.1 calls itself the stable release line; depends on its core and zod ≥ 4.2; its core lists
protocol versions back to 2024-10-07 (negotiated 2025-06-18 with our probe); tools via `registerTool(name, {inputSchema:
z.object(…), annotations}, handler)`; stdio via `serveStdio(factory)` from `@modelcontextprotocol/server/stdio`.

## VF61 (2026-10-15) — Oranfresh OJ-130 published capacity [believed — vendor catalogue 2025, through research]
55 kg ≈ 440 oranges per load; 100–130 cups at 200–300 ml; serving 30–35 s; automatic cleaning. Not FreshNow's numbers — the cups
per carton used by reconciliation is calibrated from FreshNow's own data later (A-T55.x).

=====assumptions.md
## A-T55.1 — Portal export times are Asia/Dubai local time [believed]
Every minute-level match between exports and the API's UTC timestamps worked with +04:00, but Televend does not document it.
Confirm/refute: Televend documentation, or an export taken at a known moment. Affects: `parseDubaiLocal` (files.ts).

## A-T55.2 — Refill fill_type 2 means "Removed" and source 3 means "Televend" [assumed]
The CSV shows Removed/Televend rows; the live codes for them were not seen. Until seen, they map to "unknown". Confirm/refute: a
live refill row whose CSV twin says Removed. Affects: REFILL_FILL_TYPE / REFILL_SOURCE (types.ts).

## A-T55.3 — `api.televendcloud.com` is the official API's production gateway [assumed]
Inferred from DNS; only the UAT gateway is documented. Confirm/refute: Televend IT at onboarding. Affects: allowlist HOSTS.

## A-T55.4 — Televend's cash-collection records carry the machine's own cash figures [believed]
The spec's CashCollection has cashIncome, cashLeftInMachine and denominations; never seen live (403 for this account).
Confirm/refute: the official API's demo mode, or a user with cash-centre view. Affects: expected cash in TASK-062.

## A-T55.5 — Reading Televend through a web user is acceptable under FreshNow's Televend contract [assumed]
No terms of use are published; the bridge uses the web app's own read endpoints, paced. Confirm/refute: FreshNow's Televend
contract or Televend. Removed entirely by the official API.
